# Подсчёт калорий — Telegram-бот @count_kcal_bot

Пишешь боту, что съел: текстом («банка тунца, 3 варёных яйца, кофе с молоком») или фото — блюда, этикетки,
штрихкода. Бот считает калории и БЖУ, ведёт дневник по дням и показывает итоги.

- текст и фото блюда оценивает нейросеть DeepSeek, этикетку она читает с фото;
- штрихкод бот читает сам и берёт числа с упаковки из [Open Food Facts](https://world.openfoodfacts.org)
  и [Роскачества](https://rskrf.ru) — без нейросети.

Стек: Node 24 (TypeScript без сборки), [grammY](https://grammy.dev), `node:sqlite`, DeepSeek, zxing-wasm.

## Команды

| Команда | Что делает |
|---|---|
| текст или фото | записать еду и показать итог за день; под ответом кнопка «↩️ Отменить» |
| подпись к фото | уточнение: «это 300 г», «съел половину» |
| альбом | несколько фото одним сообщением — одна запись |
| `/today` | еда за сегодня |
| `/week` | 7 дней по дням и среднее |
| `/undo` | удалить последнюю запись |
| `/clear` | удалить всё за сегодня (с подтверждением) |

Продукт, калории которого оценить не удалось, бот не записывает и просит уточнить.
Бот отвечает только в личных сообщениях и только тем, кто указан в `ALLOWED_USER_IDS`.

## Запуск

Нужны Node 24+ (`nvm use` возьмёт версию из `.nvmrc`), токен бота от [@BotFather](https://t.me/BotFather)
и ключ [DeepSeek](https://platform.deepseek.com/api_keys).

```bash
npm ci
cp .env.example .env    # и заполнить
npm run dev             # бот с перезапуском при изменении файлов
```

Проверки: `npm run typecheck`, `npm run lint`, `npm test` (тесты не ходят в сеть).

## Настройки (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `DEEPSEEK_API_KEY` | да | ключ DeepSeek |
| `TZ` | нет (UTC) | таймзона, по которой считаются дни, например `Europe/Moscow` |
| `DB_PATH` | нет (`./kcal.db`) | файл SQLite |
| `ALLOWED_USER_IDS` | нет (все) | кому можно пользоваться ботом, через запятую. Пусто — любой, кто найдёт бота, тратит баланс DeepSeek |

## Выкат

Push в `master` → GitHub Actions проверяет код и выкатывает его на сервер в Docker (`.github/workflows/deploy.yml`).
Если проверки упали, продолжает работать прошлая версия. `.env` лежит только на сервере, база — на Docker-томе,
раз в неделю бэкап (`scripts/backup-db.ts`).

На сервере, в `/opt/count-kcal-bot`:

```bash
docker compose logs -f -t     # логи
docker compose up -d          # перезапуск, в том числе после правки .env
docker compose stop           # остановить: бот доработает начатое и закроет базу
```

Бот с одним токеном работает только в одном месте: локальный запуск с токеном с сервера получит `409 Conflict`.
Для разработки заведи отдельного бота в BotFather.

## Если что-то не так

- `ERR_UNKNOWN_FILE_EXTENSION ".ts"` — запустился старый Node, нужен 24+.
- `401 Unauthorized` при старте — неверный `BOT_TOKEN`.
- `409 Conflict` — бот уже запущен где-то ещё.
- `DeepSeek HTTP 401/402` — неверный ключ или кончился баланс.
- Бот отвечает «ошибка нейросети» — подробности в логах бота.
