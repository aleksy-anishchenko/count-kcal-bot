# Подсчёт калорий — Telegram-бот @count_kcal_bot

Пишешь боту свободным текстом: «банка тунца, 3 варёных яйца, кофе с молоком», или присылаешь
фото: блюдо, упаковку с таблицей калорийности или штрихкод. Бот одним запросом в DeepSeek превращает это
в JSON со списком продуктов, считает калории и БЖУ, сохраняет в SQLite по дням и показывает итоги.
Штрихкод читается локально и ищется в двух открытых базах, Open Food Facts и Роскачество, без нейросети.

**Стек:** Node ≥ 24, TypeScript без сборки, [grammY](https://grammy.dev) + [runner](https://grammy.dev/plugins/runner), `node:sqlite`, `node:test`, DeepSeek (`deepseek-flash`) через `fetch`,
[zxing-wasm](https://github.com/Sec-ant/zxing-wasm) для штрихкодов, [Open Food Facts](https://world.openfoodfacts.org) и [API Роскачества](https://rskrf.ru/about/dev/) как базы продуктов.
Runtime-зависимости — `grammy`, `@grammyjs/runner` и `zxing-wasm` (декодер штрихкодов на WebAssembly, без нативных модулей).

Сообщения обрабатываются параллельно (runner): пока нейросеть думает над сообщением
одного человека, другие не ждут. Сообщения одного человека идут строго по очереди (`sequentialize`).

## Требования

- **Node 24+.** Нужен именно 24: он запускает `.ts`-файлы напрямую и даёт `node:sqlite` без флагов.
  Проверить: `node --version`.
  Если пользуешься nvm: в проекте лежит `.nvmrc`, так что `nvm install 24` один раз, а дальше `nvm use` в папке проекта
  (или автоматически, если в `.zshrc` настроен хук на `.nvmrc`).
- Токен бота — создать у [@BotFather](https://t.me/BotFather) командой `/newbot`.
- Ключ DeepSeek — [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys).

## Запуск

```bash
npm ci                      # зависимости ровно по package-lock.json (typescript и eslint — только для разработки)
cp .env.example .env        # и заполняем BOT_TOKEN, DEEPSEEK_API_KEY, TZ, ALLOWED_USER_IDS
npm start                   # node --env-file=.env src/main.ts
```

Для разработки — `npm run dev`: то же самое, но Node перезапускает бота при изменении файлов (как HMR, только грубее).

Проверка типов (сборки нет, это просто линтер типов): `npm run typecheck`.
Линтер: `npm run lint` — ESLint с правилами typescript-eslint, которые смотрят на типы
(например, ловят промис без `await`). Настройки — `eslint.config.js`.

Тесты: `npm test`. Это встроенный `node --test`, без зависимостей. Он читает `.env.test`
(заглушки вместо токенов, база в памяти) и находит все `*.test.ts` в `src/` и подпапках. В Telegram и DeepSeek тесты не ходят:
`bot/create-bot.test.ts` прогоняет бота целиком с подменённым Telegram (`bot/fake-telegram.ts`) и подменённым `fetch`.

## Команды

| Команда | Что делает |
|---|---|
| любой текст | распознать продукты, оценить калории и БЖУ, сохранить, показать итог за день. Под ответом — кнопка «↩️ Отменить» для именно этой записи |
| фото | то же самое по фото блюда или упаковки с таблицей калорийности. Подпись к фото уходит в модель вместе с картинкой: «это 300 г», «съел половину». Под ответом пометка: «По этикетке» или «Оценка по фото, приблизительная» |
| фото штрихкода | товар ищется по штрихкоду сначала в Open Food Facts, потом в Роскачестве; числа берутся с упаковки, без нейросети. Порция: граммы из подписи, иначе вся упаковка. Подпись без граммов («съел половину») считает нейросеть по числам из базы. Если база знает товар, но не его калории, нейросеть один раз оценит их на 100 г по названию и составу, и следующие сканы считаются без неё. Если товара нет нигде, бот попросит снять таблицу калорийности |
| картинка файлом | JPEG или PNG до 10 МБ, тот же разбор, что у фото. Файл не сжимается, поэтому мелкий штрихкод читается лучше |
| альбом | несколько фото одним сообщением — одна запись: например, упаковка с двух сторон или блюда одного обеда |
| `/today` | еда за сегодня с суммой ккал/БЖУ |
| `/week` | 7 дней: ккал/БЖУ по дням и среднее (без сегодняшнего, ещё не законченного дня) |
| `/stats` | сколько токенов DeepSeek потрачено сегодня и за 7 дней (на весь бот) |
| `/undo` | удалить последнее сообщение целиком |
| `/clear` | удалить все записи за сегодня (бот переспросит кнопками; записи, добавленные после вопроса, не тронет) |

Бот работает только в личных сообщениях: в группах он молчит. На стикеры, голосовые и документы (кроме картинок) отвечает, что понимает только текст и фото.
Текст длиннее 1500 символов в нейросеть не уходит: бот просит сократить — так случайно вставленный документ не съест баланс.

«Сегодня» считается в таймзоне из `TZ` в `.env`, а не по часам сервера.
Запись попадает в день, когда сообщение **отправлено**, а не когда бот его обработал:
если бот был выключен ночью, вчерашний ужин всё равно запишется во вчера.

Если нейросеть не смогла оценить продукт, вместо числа будет «?», а итог помечен ⚠️ — реальная сумма больше.
Если не смогла оценить ни одного продукта в сообщении (текст или фото), запись не сохраняется: бот говорит, что уточнить.
Если тот же текст пришёл повторно в течение 30 минут, бот запишет его, но предупредит: вдруг это случайный дубль.
При временной ошибке DeepSeek (429, 5xx, обрыв сети) бот один раз повторяет запрос через 2 секунды.

├── config.ts                  — все переменные окружения в одном месте, проверка при старте
├── hide-token-in-logs.ts      — патч консоли: прячет токен бота в логах (подключается первым)
│
├── bot/                       — Telegram (grammY). Не пишет SQL и не знает API нейросети и баз товаров
│   ├── create-bot.ts          — собирает бота: альбомы → очередь → доступ → features/ → обработчик ошибок
│   ├── context.ts             — тип ctx: стандартный плюс ctx.album
│   ├── album.ts               — middleware: фото одного альбома ждут друг друга секунду и идут вместе
│   ├── access.ts              — middleware: только личные чаты и ALLOWED_USER_IDS
│   ├── error-handler.ts       — упавший обработчик → лог и ответ («ошибка нейросети» или «что-то пошло не так»)
│   ├── command-menu.ts        — меню команд (кнопка «/» в Telegram)
│   ├── save-entry.ts          — общий финал текста и фото: сохранить, ответить, кнопка «↩️ Отменить»
│   ├── format.ts              — как показываем числа, даты, продукты, итоги, пометку «откуда числа»
│   ├── telegram-helpers.ts    — длинные сообщения, безопасное редактирование, скачивание файла
│   ├── fake-telegram.ts       — бот без Telegram, для create-bot.test.ts
│   └── features/              — по файлу на функцию бота: help, today, week, stats, undo, clear,
│                                text-entry, photo-entry (фото, картинки файлом, альбомы)
│                                и unhandled (всё остальное, подключается последним)
│
├── recognition/               — «что съедено»: текст или фото → продукты с КБЖУ. Без Telegram
│   ├── types.ts               — общие типы: FoodItem, NutritionSource, Recognition, Image
│   ├── recognize-food.ts      — запрос в нейросеть: текст и/или фото → Recognition; расход токенов; ошибки AiError
│   ├── recognize-photo.ts     — порядок шагов для фото: штрихкод → базы → нейросеть
│   ├── estimate-nutrition.ts  — калории на 100 г для товара без чисел в базе, с сохранением в кэш
│   ├── deepseek.ts            — HTTP-клиент DeepSeek: таймаут, один повтор при 429/5xx
│   ├── prompt.ts              — системный промпт
│   └── normalize.ts           — проверка JSON от модели: числа строками, пропавшие поля, мусор
│
├── products/                  — товары по штрихкоду
│   ├── product.ts             — тип Product и проверка hasNutrition
│   ├── barcode.ts             — чтение штрихкода с фото (zxing-wasm) и контрольная цифра
│   ├── find-product.ts        — кэш (свежий — до 90 дней) → Open Food Facts → Роскачество
│   ├── portion.ts             — пересчёт «на 100 г» в съеденную порцию
│   ├── product-prompt.ts      — тексты для нейросети о товаре: посчитать порцию или оценить на 100 г
│   └── sources/               — по файлу на базу: open-food-facts.ts, roskachestvo.ts; user-agent.ts

Тесты лежат рядом с кодом, который проверяют: `portion.ts` → `portion.test.ts`.

Функции вызываются только «вниз»: `bot/` → `recognition/` → `products/` → `db/` → `utils/`.
Обратно идут лишь `import type` общих типов (`FoodItem`, `Product`): Node их вырезает, циклов при запуске нет.
Если проводить аналогию с Vue-приложением: `main.ts` — тот же `main.ts` с `createApp`, `bot/create-bot.ts` — роутер,
`bot/features/` — страницы, `recognition/` и `products/` — сервисы из `api/` и composables,
`db/` — Pinia-store, `utils/` — `utils/`, `config.ts` — обёртка над `import.meta.env`.

**Поток данных для сообщения «банка тунца, 3 варёных яйца»:**

1. `bot/features/text-entry.ts` ловит текст и показывает «печатает…».
2. `recognition/recognize-food.ts` отправляет текст в `deepseek-flash` с `response_format: json_object`,
   выключенным режимом размышлений и системным промптом, где описан формат. Ответ — строка с JSON.
3. `recognition/normalize.ts` разбирает JSON и **прогоняет через валидацию**: нейросеть может
   вернуть число строкой или пропустить поле, поэтому объект собираем заново.
4. `db/entries.ts` в одной транзакции пишет запись в `entries` и продукты в `food`.
5. `bot/save-entry.ts` отвечает: что распознано + сумма ккал за день.

Если нейросеть не ответила, `recognizeFood` бросает `AiError`. Обработчик её не ловит: она долетает до
`bot/error-handler.ts`, и тот отвечает «ошибка нейросети». Так ответ на ошибку описан в одном месте.

**Для фото нейросети не нужно «понимать», что на снимке** — решает порядок шагов в
`recognition/recognize-photo.ts`, дешёвые и точные первыми:

1. `products/barcode.ts` ищет штрихкод локальным декодером (десятки миллисекунд, без сети).
2. Нашёл — `products/find-product.ts` берёт товар из кэша `products` или спрашивает базы по очереди: Open Food Facts,
   потом Роскачество. Товар с калориями есть — числа с упаковки, порция из подписи или вся упаковка,
   нейросеть не нужна. Есть только название (так бывает в обеих базах) — нейросеть оценивает по названию,
   весу и составу, уже без картинки. Под ответом всегда написано, откуда числа; для Роскачества со ссылкой
   на карточку, это их условие использования API.
3. Иначе — фото (и подпись) уходят в `deepseek-flash` как base64: модель читает таблицу калорийности
   или оценивает блюдо и говорит в `source`, что из двух она сделала.
4. Если модель разглядела цифры под штрихкодом, который декодер не прочитал, бот проверяет
   контрольную цифру и пробует базу ещё раз (если это не тот же код, что декодер уже искал).
5. Если в итоге ни у одного продукта нет калорий, бот ничего не записывает, а объясняет, что делать:
   товар нашёлся, но порцию не понял — просит граммы в подписи; товар без калорий — просит снять таблицу;
   штрихкод есть, товара в базе нет — тоже просит таблицу.

Товар без калорий в базе нейросеть оценивает на 100 г (`estimate-nutrition.ts`). Оценка ложится в кэш
с пометкой `nutrition_estimated`, и следующий скан считается арифметикой, без запроса. Кэш товара живёт 90 дней,
потом базы спрашиваются снова; если они не ответили — берётся устаревшая запись.
В альбоме декодер смотрит каждое фото; если штрихкода нет, все фото уходят в нейросеть одним запросом.

Декодер, базы и нейросеть передаются в `recognizePhoto` параметром, поэтому весь порядок шагов
проверяется тестами с заглушками (`recognize-photo.test.ts`), без сети.

**Схема базы (четыре таблицы):**

```
entries  (id, user_id, day 'YYYY-MM-DD', created_at, text)
food     (id, entry_id → entries, name, amount, kcal, protein, fat, carbs)
products (barcode, name, quantity, composition, kcal100…carbs100, nutrition_estimated, origin, link, fetched_at)  — кэш баз штрихкодов
ai_usage (day, requests, prompt_tokens, cached_prompt_tokens, completion_tokens)  — расход DeepSeek для /stats
```

`entry_id` с `ON DELETE CASCADE` — удалил запись, её продукты удалились сами. На этом построен `/undo`.
Индексы: `entries (user_id, day)` и `food (entry_id)` — чтобы `/today`, `/week` и `/undo` не перебирали таблицы целиком.
Запись по фото хранится с текстом «📷 подпись» или «📷 фото».

**Миграции.** Схема описана в `db/migrations.ts` массивом `MIGRATIONS`, номер применённого шага база хранит в
`PRAGMA user_version`. При старте бот применяет только недостающие шаги. Чтобы поменять схему —
допиши новую миграцию в конец массива (например, `ALTER TABLE food ADD COLUMN fiber REAL;`),
уже выпущенные не редактируй.

Калории и БЖУ для текста и фото блюда — оценка нейросети. Для бытового учёта точности хватает,
но на ±15 % рассчитывай. По фото этикетки точнее, по штрихкоду — числа с упаковки из Open Food Facts.
Open Food Facts наполняют пользователи: российских товаров там около 37 тысяч, с заполненным КБЖУ
примерно половина. Роскачество — около 9 тысяч товаров из их исследований, данные лабораторные, но КБЖУ
записано текстом и есть не у всех. Чего нет ни там, ни там, считается по фото этикетки.

## TypeScript без сборки — что это значит

Node 24 умеет запускать `.ts` напрямую: он не компилирует, а просто **вырезает типы**
(type stripping). Из-за этого есть три правила, которые tsconfig.json помогает соблюдать:

1. **В импортах — расширение `.ts`:** `import { addEntry } from '../db/entries.ts'`.
2. **Типы импортируем через `import type`.** Node не умеет понять, что `import { Recognition }`
   нужен только для типа, и попытается найти такой экспорт в рантайме.
3. **Нельзя `enum`, `namespace` и parameter properties** (`constructor(private x: number)`):
   их нельзя «вырезать», нужно компилировать. Опция `erasableSyntaxOnly` подсветит их в редакторе.

## Настройки (.env)

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `DEEPSEEK_API_KEY` | да | ключ DeepSeek |
| `TZ` | нет (UTC) | таймзона для «дней», например `Europe/Moscow` |
| `DB_PATH` | нет (`./kcal.db`) | путь к файлу SQLite; `:memory:` — база в памяти |
| `ALLOWED_USER_IDS` | нет (все) | кому можно пользоваться ботом, через запятую. Чужим бот покажет их id |

Все переменные читает и проверяет `config.ts` при старте: если чего-то не хватает или в списке
пользователей опечатка (не число), бот не запустится и покажет, что именно не так.

Стоит заполнить `ALLOWED_USER_IDS`: иначе любой, кто найдёт бота, будет тратить твой баланс DeepSeek
(при пустом значении бот напомнит об этом в консоли при старте).

## Выкат на сервер

Бот запускается в Docker. Docker сам поднимает его после падения и после перезагрузки сервера,
а Node 24 приезжает внутри образа — на сервер ставится только Docker.

**Выкат — push в `master`.** GitHub Actions (`.github/workflows/deploy.yml`) прогоняет typecheck, lint и тесты,
копирует файлы на сервер в `/opt/count-kcal-bot` через `rsync` и там выполняет `docker compose up -d --build`.
Если проверки упали, на сервер ничего не уходит и работает прошлая версия. Ход выката — вкладка Actions на GitHub.
Новые миграции база применит сама при старте.

**Один раз перед первым выкатом:**

1. На сервере — Docker (`docker compose version` должен отвечать; если нет — `curl -fsSL https://get.docker.com | sh`).
2. `.env` на сервер — в репозиторий он не попадает:
   ```bash
   ssh root@62.132.3.59 mkdir -p /opt/count-kcal-bot
   scp .env root@62.132.3.59:/opt/count-kcal-bot/.env
   ```
   Обязательно заполни `ALLOWED_USER_IDS` — иначе любой, кто найдёт бота, тратит баланс DeepSeek.
   `DB_PATH` из `.env` в Docker не используется: `compose.yaml` кладёт базу на том `data`
   (`/app/data/kcal.db`), и она переживает пересборку образа.
3. В репозитории на GitHub: Settings → Secrets and variables → Actions → секрет `SSH_PRIVATE_KEY` —
   приватный SSH-ключ, которым Actions заходит на сервер (тот же, что у сайта, или новый).

Бот с одним токеном может работать только в одном месте. Пока он работает на сервере, локальный
`npm run dev` с тем же токеном получит `409 Conflict` — для разработки заведи второго бота в BotFather.

На сервере:

```bash
cd /opt/count-kcal-bot
docker compose logs -f -t              # логи (-t — с временем каждой строки); Ctrl+C — выйти, бот работает дальше
docker compose up -d --build           # пересобрать и перезапустить вручную, без GitHub
docker compose stop                    # остановить: бот доработает начатое (до 70 с) и закроет базу
```

**Бэкап раз в сутки** — `scripts/backup-db.ts`: целостная копия через `backup()` из `node:sqlite`
(простой `cp` в WAL-режиме может потерять свежие записи), внутри тома хранит 30 последних копий.
На сервере: `sudo mkdir -p /backups`, потом `crontab -e` и строка

```
0 4 * * * cd /opt/count-kcal-bot && docker compose exec -T bot node scripts/backup-db.ts /app/data/backups && docker compose cp bot:/app/data/backups/. /backups/ && find /backups -name 'kcal-*.db' -mtime +30 -delete
```

Каждый день в 4:00: копия базы внутри тома → копии с тома в `/backups` на сервере → удалить там копии старше
30 дней. `-T` — без интерактивного терминала, у cron его нет. Совсем надёжно — время от времени уносить
`/backups` с сервера к себе: бэкап на том же диске не спасёт, если умрёт сам сервер.

## Типичные проблемы

- **`ERR_UNKNOWN_FILE_EXTENSION ".ts"`** — запустился старый Node. Нужен 24+; с nvm выполни `nvm use` в папке проекта.
- **`Cannot find .env`** — не скопирован `.env.example` → `.env`.
- **`401 Unauthorized` при старте** — неверный `BOT_TOKEN`.
- **`409 Conflict`** — бот уже запущен где-то ещё (например, дома и на сервере одновременно). Опрашивать Telegram может только один процесс.
- **`DeepSeek HTTP 401/402`** — неверный ключ или кончился баланс.
- **Бот отвечает «ошибка нейросети»** — подробности в консоли бота (`console.error`).
- **«Штрихкод прочитал, но в базах такого товара нет»** — так и есть, ни Open Food Facts, ни Роскачество его не знают. Сними таблицу калорийности на упаковке.
- **Open Food Facts или Роскачество недоступны** — бот пишет об этом в консоль, пробует другую базу, а потом разбирает фото нейросетью, как будто штрихкода не было.
- **«Роскачество: не удалось пройти cookie-защиту»** — их API отвечает редиректом с cookie, бот умеет его проходить; если защита изменилась, этот источник просто выпадает, остальное работает.
