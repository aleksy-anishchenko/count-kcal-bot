# count-kcal-bot: что осталось и что важно помнить

Как бот устроен и как его запускать — в README. Здесь то, чего нет ни в README, ни в коде:
что сделать до выката (раздел 1, после выката его можно удалить), идеи на потом
и проверенные факты с решениями — чтобы не исследовать заново и не «упрощать» то, что сделано так не зря.

Как возобновить работу:
```bash
nvm use                 # Node 24 из .nvmrc
npm ci                  # зависимости ровно по lock-файлу
npm run typecheck       # должно быть пусто
npm run lint            # должно быть пусто
npm test                # 118 тестов, все зелёные
npm run dev             # бот с перезапуском при изменении файлов
```

## 1. До выката

Файлы готовы, по шагам — README, «Выкат на сервер»:

1. **Сервер:** Docker и `.env` в `/opt/count-kcal-bot` (с `ALLOWED_USER_IDS`).
2. **GitHub:** приватный репозиторий без README, секрет `SSH_PRIVATE_KEY` — до первого push.
3. **Git** — сделаешь сам: ветка `master` (на неё настроен выкат). `.env.test` коммитить можно
   (секретов нет), `.env`, `*.db*` и `.idea/` уже в `.gitignore`.
4. **Первый push** — смотреть вкладку Actions. Образ ещё ни разу не собирался: первая сборка покажет,
   всё ли в `Dockerfile` верно. Потом остановить локальный `npm run dev` (иначе `409 Conflict`).
5. **После запуска** — отправить боту пару сообщений и фото, `docker compose logs -t` без ошибок.
6. **Cron для бэкапа** — строка из README; проверить, что копия появилась на следующий день.

## 2. Бэклог

- **Регулярки КБЖУ Роскачества** — по мере появления: покрыты 4 встреченных формата
  (`products/sources/roskachestvo.test.ts`). При первом «нашло товар, но КБЖУ не распознало» — взять текст
  из лога и добавить формат в тест.
- **Альбом и порядок сообщений.** Альбом ждёт секунду до очереди `sequentialize`, поэтому сообщение,
  отправленное в эту секунду сразу после альбома (например, `/undo`), обработается раньше альбома.
  Если станет мешать — ставить сообщения пользователя в очередь за его собирающимся альбомом.

### Известные ограничения (не баги)
- Telegram сжимает фото до ~1280 px: мелкий или смазанный штрихкод декодер может не прочитать —
  тогда страхует модель, читая цифры под полосками.
- Оценка по фото блюда «на глаз» грубее текста с граммовками; по этикетке точнее; по штрихкоду
  точнее всего, но только если товар есть в базах.
- Open Food Facts наполняют пользователи: бывают ошибки и странные числа
  (например, `36.6666666666667` ккал). Роскачество — лабораторные данные, но только ~9 000 товаров.
- Подпись к фото со штрихкодом без граммов («половину») идёт через модель, арифметика только для граммов.
- Фото альбома, пришедшее позже чем через секунду после первого, станет отдельной записью.
- `/stats` показывает расход на весь бот, а не на пользователя: платит один владелец ключа.
- Картинки файлом — до 10 МБ (Telegram отдаёт ботам до 20 МБ; больше гнать в нейросеть незачем).

## 3. Справочник проверенных фактов (на 2026-10-22)

### DeepSeek
- Модели в аккаунте: `deepseek-flash` (V4.1-Flash-1017, текст + картинки, контекст 1M) и
  `deepseek-v4-pro` (только текст). `deepseek-chat` — legacy-алиас на Flash без размышлений,
  плановое отключение было 2026-07-24; в ответе API поле `model` показывает `deepseek-flash`.
- Размышления выключаются `thinking: { type: 'disabled' }` в теле запроса (по умолчанию включены, `effort: high`).
- Картинка: блок `{ type: 'image_url', image_url: { url: 'data:image/jpeg;base64,…' } }` только
  в `user`-сообщении; до 1024 токенов на картинку; `detail: 'low'` сжимает до 512 px (не для этикеток).
- `response_format: { type: 'json_object' }` + картинка + выключенные размышления — работают вместе
  (проверено запросом). В промпте должно быть слово «JSON» и пример.
- Цены с сайта не вытащить скриптом (рендерятся JS): смотреть глазами на Models & Pricing.
- PNG и несколько картинок в одном `user`-сообщении принимаются (проверено 2026-10-22: две PNG — HTTP 200).
- `usage` в ответе: `prompt_tokens`, `completion_tokens`, `total_tokens`, `prompt_cache_hit_tokens`,
  `prompt_cache_miss_tokens`, `prompt_tokens_details.cached_tokens`. Системный промпт частично попадает в кэш
  (128 из 985 токенов в проверочном запросе).

### Open Food Facts
- `GET https://world.openfoodfacts.org/api/v2/product/<штрихкод>.json?fields=…`; 404 — товара нет.
- Поля: `product_name_ru`, `product_name`, `brands`, `quantity`, `ingredients_text_ru`,
  `nutriments.energy-kcal_100g|proteins_100g|fat_100g|carbohydrates_100g` (на 100 г, бывают строками).
- Условия: описательный `User-Agent`; один запрос = одно реальное сканирование (поэтому кэш).
- Поиск (`/api/v2/search`) жёстко ограничен по частоте — третий запрос подряд уже «Page temporarily
  unavailable». Запрос одного товара — нет. Россия: ~36 900 товаров, ~17 570 с заполненным КБЖУ.

### Роскачество (rskrf.ru/about/dev)
- Бесплатно, без ключа; условие — активная ссылка на портал (бот показывает `product_link`).
- `GET https://rskrf.ru/rest/1/search/barcode?barcode=<код>` → `{ response: {...} }`; нет товара —
  `{ response: {}, message: [] }`. Есть ещё `/product/{id}/`, `/search/product?query=…&page=…`,
  каталог по категориям. Данные обновляются раз в неделю, ~9 000 товаров.
- Защита: первый запрос → 302 на тот же URL с `Set-Cookie: __hash_=…; Max-Age=1800`; с cookie → 200.
  В Node: `fetch(url, { redirect: 'manual' })`, взять `set-cookie`, повторить с `Cookie`.
- Карточка: `title`, `product_link`, `product_info[{name, info}]` (поля «Вес», «Состав», «Штрихкод(ы)»,
  «Дополнительная информация» с текстом КБЖУ), `criteria_ratings`, `worth`, `disadvantage`.
- Форматы КБЖУ в тексте, покрытые регулярками: «белки - 16,0 г, … калорийность - 120 ккал»;
  «белок - 13,0 г, жир - 11,0 г, … 630 кДж/150 ккал»; «жир 28,5 г, белок 24,5 г … 354 ккал/1480 кДж»;
  «белки- 7,0г; жиры- 32,0г (в том числе насыщенные жирные кислоты- 18,3); углеводы- 56,0» без ккал
  (считаем 4/9/4). У многих карточек КБЖУ нет вовсе.

### Отвергнутые источники
- Национальный каталог (Честный знак): API есть, с КБЖУ, но `apikey` только участникам
  маркировки с ролью «Администратор»; открытых страниц товаров нет (404).
- barcode-list.ru: только названия, без API (парсинг HTML), robots.txt `Crawl-delay: 10`.
  Оба наших штрихкода находит. Отклонён как хрупкий; запасной вариант, если понадобятся названия.
- Dietagram (RapidAPI): бесплатно 10 штрихкодов/день, русский поддерживается, покрытие РФ не проверено.
  Решено не подключать (2026-10-22): нужен отдельный аккаунт и ключ, а двух баз хватает.
- food-bd.com: платно, от 2 990 ₽/мес, ~32 000 товаров РФ и РБ со штрихкодами.
- USDA FoodData Central (США), FatSecret (штрихкод только в платном Premier), Edamam (от $14/мес).

### Библиотеки и платформа
- zxing-wasm 3.1.6: `import { readBarcodes } from 'zxing-wasm/reader'`; в Node `.wasm` отдать самим:
  `prepareZXingModule({ overrides: { wasmBinary } })`, путь через
  `import.meta.resolve('zxing-wasm/reader/zxing_reader.wasm')`. Форматы на вход `'EAN-13'`,
  в результате `'EAN13'`. Фото 1280 px читается за ~19 мс. Writer (`zxing-wasm/writer`) используется в тесте.
- node:sqlite: строки приходят с null-прототипом (в тестах сравнивать через `{ ...row }`);
  `enableForeignKeyConstraints` включён по умолчанию; `DatabaseSync(path, { timeout })`;
  `':memory:'` работает; снять `NOT NULL` можно только пересозданием таблицы (миграция 3 — образец);
  `ADD COLUMN … NOT NULL DEFAULT …` работает через `ALTER` (миграция 4). `backup(db, path)` из `node:sqlite`
  делает целостную копию при WAL (`scripts/backup-db.ts`); `new DatabaseSync` на несуществующий путь создаёт пустую базу.
- Node 24.17: `node --test` сам находит `**/*.test.ts`; `--env-file` работает; `ExperimentalWarning`
  для `.ts` и `node:sqlite` больше нет.
- grammY runner 2.0.3: при 401/409 падает сразу, при сетевых ошибках повторяет 15 часов;
  `stop()` не ждёт обработчики — ждём сами по `runner.size()`. Ошибку обработчика runner передаёт в
  `bot.errorHandler` (его задаёт `bot.catch`); `bot.handleUpdate` сам ошибку пробрасывает — в тестах её
  отдаём в `bot.errorHandler` так же (`fake-telegram.ts`).
- grammY: `Composer.on('message').filter(предикат, обработчик)` — обработчик только для подходящих
  апдейтов, остальные идут дальше; context flavor — `Bot<Context & { album?: Message[] }>`. Альбом приходит
  отдельными апдейтами с общим `media_group_id`, почти одновременно; подпись — обычно у одного фото.
- typescript-eslint: `test()` из `node:test` возвращает промис — для `no-floating-promises` есть
  `allowForKnownSafeCalls` с `{ from: 'package', package: 'node:test' }`.
- Telegram: фото приходит сжатым JPEG в нескольких размерах, последний в `message.photo` — самый большой
  (бот качает по его `file_id` через `ctx.api.getFile`); картинка «файлом» — документ со своим `mime_type`, без сжатия;
  URL файла содержит токен бота (патч консоли его прячет); лимит сообщения 4096;
  `link_preview_options: { is_disabled: true }` отключает превью ссылок.

## 4. Журнал решений

| Решение | Почему |
|---|---|
| Все env в `config.ts`, модули не читают `process.env` | одна точка проверки при старте; модули можно импортировать в тестах с заглушками |
| `hide-token-in-logs.ts` первым импортом | порядок выполнения ES-импортов: патч консоли должен встать раньше, чем кто-то напечатает |
| `deepseek-flash` + `thinking: disabled` | алиас `deepseek-chat` устарел; размышления для JSON-разбора лишние и могут съесть `max_tokens` |
| Встроенный `node:test`, не vitest/jest | ноль зависимостей; Node 24 сам находит `.test.ts` |
| Декодер штрихкода до нейросети | бесплатно и за миллисекунды; нейросети не нужно «понимать», что на фото |
| Open Food Facts раньше Роскачества | числа полями надёжнее, чем регулярки по тексту; товар с калориями важнее «только названия», поэтому вторая база всё равно спрашивается |
| Кэш `products` | условие Open Food Facts «один запрос = одно сканирование»; повторный скан мгновенный |
| Не парсить barcode-list.ru | хрупко (HTML чужого сайта), только названия; Роскачество закрыло ту же потребность официальным API |
| Запись без единой калории не сохраняется — ни по фото, ни по тексту | запись из одних «?» давала день «0 ккал» и занижала среднее за неделю; лучше объяснить, что уточнить. Частично оценённая сохраняется с «?» и ⚠️, чтобы неоценённый продукт не пропал молча |
| Название товара и текст записи — без кавычек вокруг | в названиях и в тексте бывают свои «», и получалось «Напиток «Загадочный»» |
| Проверка повторов только для текста | фото без подписи хранятся как «📷 фото» и выглядели бы дублями |
| Миграция 3 пересоздаёт `products` | SQLite не снимает `NOT NULL` через `ALTER`; образец на будущее |
| Ссылка на Роскачество под записью | единственное условие их API; превью ссылки выключено, чтобы не занимать экран |
| Папки по слоям (`bot/`, `recognition/`, `products/`, `db/`, `utils/`), а не плоский `src/` | видно, где Telegram, а где логика; вызовы идут только вниз, вверх — лишь `import type` |
| По `Composer` на функцию бота в `bot/features/` | приём из документации grammY («Scaling Up»); команда и её кнопки живут в одном файле |
| `recognizePhoto(photo, steps)` с шагами параметром | порядок шагов тестируется заглушками без сети; в боевом коде `steps` по умолчанию настоящие |
| `AiError` + ответ в `bot/error-handler.ts` | обработчики не ловят ошибки сами; ошибки базы не выдаются за «ошибку нейросети» |
| Строки базы в camelCase через `AS` | в TypeScript не протекает `created_at`; схема базы не меняется |
| Альбом собирается middleware до `sequentialize`, с `ctx.album` (context flavor) | иначе фото альбома ждали бы друг друга в очереди; одна запись на альбом — так человек и думает о «фото обеда» |
| Все фото альбома — одним запросом к нейросети | модель видит упаковку с двух сторон сразу и не задваивает продукт; дешевле, чем запрос на каждое фото |
| Оценка нейросети на 100 г, а не на порцию, и в кэш | одну оценку можно пересчитать на любую порцию без нового запроса |
| Устаревший кэш лучше, чем ничего | если базы недоступны, товар старше 90 дней всё равно найдётся |
| Учёт токенов, а не рублей | цены DeepSeek меняются и не читаются скриптом; токены — точные |
| Docker, а не systemd | на сервере ставится только Docker, Node 24 едет в образе; тот же запуск можно проверить на Mac. файл для systemd удалён 2026-10-22 |
| Ротация логов в `compose.yaml` (3 × 10 МБ) | по умолчанию Docker копит логи без предела и со временем забивает диск |
| Выкат: GitHub Actions → `rsync` → `docker compose up --build` на сервере | та же схема, что у сайта (`match-results-old`); серверу не нужен доступ к GitHub, `.env` живёт только на сервере |
| Бэкап через `node:sqlite` `backup()`, а не `sqlite3` CLI | на сервере и в Docker не нужна лишняя утилита; копия целостная при WAL |
| Тесты рядом с кодом, общие данные в `products/test-fixtures.ts` | `node --test` находит `*.test.ts` в подпапках сам; файл без `.test` не запускается как тест |
